## M6_V01_Why_Perception_Comes_After_Fixed_Targets_[F]

### Purpose

Introduce the transition from fixed targets to runtime detected targets.

### Story question

> In the previous module, we told the robot where the object was. But what if the object position changes?

### Content

* Review Module 5 fixed pick/place.
* Explain the limitation of fixed poses.
* Introduce RGB-D perception.
* Explain the new goal: detect object pose at runtime.
* Show the full perception-to-pick pipeline.

### Output

Students understand why perception is the next step after fixed pick/place.

## M6_V13_Debugging_Perception_Frame_Depth_and_Timing_Failures_[S]

### Purpose

Teach systematic debugging for perception-driven robotics.

### Story question

> When the robot sees the object in the wrong place, what should we check first?

### Content

Debug:

* wrong camera frame
* optical frame confusion
* `base → camera` vs `camera → base`
* wrong target frame
* depth holes
* noisy depth
* bad HSV threshold
* wrong object contour
* timestamp mismatch
* QoS issue
* point cloud offset
* stale TF
* object pose jumps

Your Module 6 plan lists failure modes such as misaligned extrinsics, unstable point clouds, and planning collisions from wrong map frames or update rates.

### Output

Students can debug perception-driven manipulation problems.
