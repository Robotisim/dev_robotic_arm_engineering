

# Module 2 Lesson Plan

## M2_V01_From_Robot_Model_to_Safe_Joint_Motion_[F]

### Purpose

Introduce Module 2 and explain the shift from robot description to robot motion.

### Story question

> Now that ROS 2 understands the robot, how do we move it safely?

### Content

Explain:

* what joint control means
* why safety matters
* why joint limits matter
* difference between visualization and control
* what students will build and test

### Output

Students understand the purpose of Module 2.

---

## M2_V02_ros2_control_Controller_Manager_and_Control_Pipeline_[A]

### Purpose

Explain the control architecture visually before running commands.

### Story question

> When we send a joint command, which ROS 2 components make the robot move?

### Content

Explain:

```text
JointTrajectory command → controller → hardware/simulation interface → joint state → TF/RViz
```

Introduce:

* controller manager
* joint state broadcaster
* trajectory controller
* command interfaces
* state interfaces

### Output

Students understand the basic `ros2_control` pipeline.

---

## M2_V03_Stick_Arm_Controller_Config_and_Bringup_[S]

### Purpose

Bring up stick arm controllers and inspect the controller config.

### Story question

> How do we tell ROS 2 which joints can be controlled?

### Demo command

```bash
ros2 launch robotic_arm_bringup sim_robot.launch.py robot:=stick_arm
```

### Content

Open and explain:

* `stick_arm/controllers.yaml`
* joint list
* controller name
* command interface
* state interface
* joint state broadcaster

### Output

Students understand how the stick arm controller is configured.

---

## M2_V04_Reading_Joint_States_and_Understanding_Feedback_[S]

### Purpose

Show that robot control requires feedback, not just commands.

### Story question

> How do we know where the joints actually are?

### Demo command

```bash
ros2 topic echo /joint_states
```

### Content

Explain:

* joint positions
* joint velocities
* joint names
* live feedback
* command vs measured state
* why feedback matters

### Output

Students can inspect live joint states.

---

## M2_V05_Commanding_Safe_Joint_Trajectories_on_Stick_Arm_[S]

### Purpose

Command the stick arm using a joint trajectory.

### Story question

> How do we move multiple joints together in a controlled way?

### Demo command

```bash
ros2 topic pub --once /stick_arm_controller/joint_trajectory trajectory_msgs/msg/JointTrajectory "{joint_names: [joint1, joint2, joint3, joint4], points: [{positions: [0.4, 0.3, -0.2, 0.1], time_from_start: {sec: 3}}]}"
```

### Content

Explain:

* `JointTrajectory`
* joint names
* positions
* time from start
* safe motion
* why joint order matters

### Output

Students can command the stick arm safely.

---

## M2_V07_Panda_Controller_Config_and_Ready_Pose_[S]

### Purpose

Scale the same joint control idea from stick arm to Panda.

### Story question

> Does the same joint control idea work on a real 7-DOF robot model?

### Demo commands

```bash
ros2 launch robotic_arm_bringup sim_robot.launch.py robot:=panda
```

```bash
ros2 topic pub --once /joint_trajectory_controller/joint_trajectory trajectory_msgs/msg/JointTrajectory "{joint_names: [panda_joint1, panda_joint2, panda_joint3, panda_joint4, panda_joint5, panda_joint6, panda_joint7], points: [{positions: [0.0, -0.785, 0.0, -2.356, 0.0, 1.57, 0.785], time_from_start: {sec: 3}}]}"
```

### Content

Explain:

* Panda joint naming
* 7-DOF complexity
* controller YAML
* safe ready pose
* joint order
* why limits matter more on real robots

### Output

Students can command Panda to a safe pose.

---

## M2_V08_Homing_Calibration_Offsets_and_Repeatability_[A]

### Purpose

Introduce calibration and homing as real robot requirements.

### Story question

> If a real robot starts in an unknown position, how does it know where zero is?

### Content

Explain:

* homing
* zeroing
* encoder reference
* offsets
* repeatability
* joint direction signs
* real hardware differences

Use analogy:

> Calibration is like tuning a guitar before playing a song.

### Output

Students understand why simulation and real hardware differ.

---

## M2_V09_Forward_Kinematics_Joint_Angles_to_End_Effector_Pose_[A]

### Purpose

Introduce FK conceptually and visually.

### Story question

> If we know all joint angles, how do we know where the gripper is?

### Content

Explain:

* joint angles
* chain of transforms
* end-effector pose
* FK as joint space to pose conversion
* how TF already reflects this chain
* why FK is needed before IK

Use this flow:

```text
joint angles → link transforms → end-effector pose
```

### Output

Students understand FK as the bridge from joint motion to gripper position.

---

## M2_V10_FK_vs_TF_Check_and_Debugging_[S]

### Purpose

Validate FK using TF.

### Story question

> How do we verify that our FK calculation matches what ROS 2 is publishing?

### Content

Explain:

* read joint states
* compute expected pose
* read TF pose
* compare position/orientation
* identify mismatch causes

Debug:

* wrong joint order
* flipped joint axis
* wrong origin
* wrong frame name
* wrong units

### Output

Students can validate FK against TF.

### Purpose

Summarize Module 2 and prepare students for IK.

> Now that we can move joints and understand FK, what comes next?

### Content
