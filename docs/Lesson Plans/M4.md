## M4_V01_Why_MoveIt_After_IK_and_Trajectories_[F]

### Purpose

Introduce why MoveIt is needed after students already learned IK and Cartesian trajectories in Module 3.

### Story question

> We can move the end-effector with IK now, but how do we plan safely when obstacles, constraints, and controllers are involved?

### Content

* Review what Module 3 achieved.
* Explain the limitation of manually sending IK trajectories.
* Introduce MoveIt as a planning and execution framework.
* Explain that MoveIt handles planning requests, collision checking, kinematics, and execution.
* Define Module 4 success criteria.

### Output

Students understand that Module 4 is not replacing IK knowledge; it is building a professional planning layer on top of it.

## M4_V07_Planning_Scene_and_Collision_Intuition_[A]

### Purpose

Build visual understanding of collision-aware planning.

### Story question

> Why does the robot need a map of the world, not just a goal point?

### Content

Explain:

* planning scene
* robot collision geometry
* world collision geometry
* obstacle objects
* collision checking
* padding
* direct path vs safe path
* why scene mismatch causes dangerous behavior

### Analogy

> Planning without a planning scene is like walking through a room with your eyes closed. You may know where you want to go, but you do not know what you might hit.

### Visual process

1. Show robot moving directly to a goal and hitting an obstacle.
2. Add obstacle to planning scene.
3. Show direct path blocked.
4. Show planner finding alternate path.
5. Increase padding and show more conservative path.

### Output

Students understand that collision checking is a safety gate, not just a visualization feature.

# Module 5 Scope

## Module 5 title

**Pick and Place with Fixed Targets, Approach/Retreat, and Gripper Timing**

## Core module description

Module 5 teaches students how to build a **repeatable pick-and-place routine** using known target poses. This is the first real manipulation module. Students are not using perception yet. They are using fixed object and place poses, structured approach/retreat motions, MoveIt planning, gripper commands, and cycle testing.

This module should feel like:

```text
We know where the object is.
We know where to place it.
Now we must design a reliable manipulation sequence.
```

Your current Module 5 plan defines the goal as executing repeatable pick-and-place using pre-defined target poses and approach/retreat motions, with Panda used for the full workflow.

## Main story of Module 5

In Module 4, students learned:

> How do we plan a safe path?

In Module 5, the question becomes:

> How do we combine multiple planned motions into a complete manipulation task?

The main pipeline is:

```text
home → pre-grasp → approach → grasp/attach → lift → move to place → release/detach → retreat → home
```
